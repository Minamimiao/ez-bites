## Project intro

We are creating EZ Bites, a web application for online food ordering and menu management, built for a single restaurant. It provides two web interfaces connected to a single PostgreSQL database and Express backend: a public page for customers to view the menu and place orders, and a dashboard for the restaurant owner to manage menu items and view incoming orders. At its base, customers will be able to add to cart, and place orders from the restaurant.

## Team philosophy

The four of us are new to web development, but we aim to undertake a real-world application by developing a functional website. One of our main reasons for choosing this project is that it provides us with an opportunity to build a concrete web platform and a manageable starting point. 

**The core goals:**

Our primary goal is to acquire a better understanding of how a full-stack web application is designed, documented, and implemented across frontend, backend, and database systems. If time permits, we intend to further explore more website features and improvements.

**The philosophies:**
- We understand mistakes are human, and we aim to help each other through them without blame.
- Active communication is important. We believe in communicating often to make sure everyone is on the same page.
- Reviewing each other’s documentation and testing application deliverables early to ensure the best quality.
- Helping each other when one person might not be able to take on their workload by re-delegating tasks.

## Planned team meeting time(s) and communication plans

Our communication tool outside of meetings is Discord, which has been set up and managed by our team. Every team member will check Discord regularly to respond to messages and ensure no updates are missed.

We will hold our primary weekly meeting on Monday from 12:00 pm to 1:00 pm, preferably in person, with an online option for members who cannot attend physically. The project manager will set an agenda (posted to the discord) at least 48 hours in advance so team members have a chance to prepare for the routine meeting. During our meetings, we will talk about our recent progress and any issues and review upcoming tasks and deadlines.

If a team member becomes regularly absent, radiosilent, or falling behind in their work then we will have one team member reach out to them via Discord and offer support. If things aren’t resolved then the issue will be raised with the course instructor.

## Deadlines and deliverables

We will use team meetings to plan upcoming deadlines and monitor project progress. Here we will review team members' work and ensure it is prepared for submission.

Each team member should complete their assigned work at least 24 to 48 hours before the deadline. We aim to have them ready 48 hours in advance. This gives us extra time to solve problems and fix unexpected bugs without rushing.

All documents and code must be verified before submission. Documentation drafts are peer-reviewed in Google Docs and undergo a final check by the documentation lead (Mira). Code changes undergo automated linter/validator checks and structured self-review by the developer (Jiamiao), followed by functional testing.

Missing deadlines creates stress for the team. If someone falls behind, we will talk to them and offer support. We will discuss whether they are facing technical hurdles or workload imbalances, and we will help them catch up. 

## Addressing Instructor Feedback

To make sure we address every issue from the instructor's feedback for each deliverable, our team will follow a simple process. After we receive feedback on any project phase, we will read and discuss all the comments together in our next team meeting.

We will write down every comment in a shared checklist. We will then assign each item on the list to a team member to fix, with a clear deadline.

Once a team member fixes their part, another team member will review the work. Before we submit the next phase deliverable, we will check the list one last time to make sure we did not miss any instructor feedback.

## Conflict resolution scheme

We will first strive to resolve conflicts through open and respectful discussion. If no agreement can be reached, the issue will be decided by a team vote. For disagreements over features or technical approaches, we will compare the pros and cons based on project requirements and available time. Unresolved non-technical issues will be consulted with Dr. Wessels.

## Team AI policies

We can leverage AI as a learning tool for our project, such as exploring programming languages, features, and techniques, getting clarification on correct language usage, and investigating error messages. 

We should also make more responsible use of AI tools. We will avoid directly copying and pasting AI-generated code. Any AI-generated code we use must be fully understood by the developer, including its logic, purpose, and functionality. This will ensure that the developer can effectively review, modify, and maintain the code later on without encountering situations where we do not understand why a particular piece of code exists or how it works.

Additionally, whenever AI tools are used to assist with learning, debugging, or code design, we will properly document and cite the AI usage in our project submissions, code comments, or documentation to maintain full academic integrity.

## Exception: Extended AI Usage (Instructor-Approved)

* **Scope & Rationale:** Certain technical infrastructure tasks—specifically configuration files, dependency management, and build and deployment setup—fall beyond the team's current technical scope. Therefore, AI tools are permitted to generate these necessary setup files and assist with system configuration.
* **Accountability & Review:** Any team member utilizing AI for these tasks remains responsible for reviewing, testing, and verifying that the generated files function properly within the project.
* **Code Standard:** Guidelines regarding AI-generated code can be found in the **Standards and procedure** document under the `documentation` directory.
* **AI Disclosure** full records of AI usage are detailed in the **AI Disclosure** document under the `documentation` directory.
